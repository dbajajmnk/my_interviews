# 2. 5W+H

## What?

AI-generated code/action evaluation verifies model-proposed artifacts before they affect systems.

## Why?

Plausible generated code may be:

- incorrect;
- insecure;
- destructive;
- inefficient;
- based on nonexistent APIs.

## Where?

Coding agents, DevOps assistants, SQL agents, automation systems.

## When?

Before execution or merge.

## How?

Generate → validate → analyze → test → sandbox/dry-run → approve → execute.

# 6. Core Concepts

## 6.1 Generated Code

Review:

- requirement fit;
- correctness;
- edge cases;
- complexity;
- security;
- dependency/API validity;
- tests.

---

## 6.2 Generated SQL

Never execute unrestricted generated SQL directly against production.

Controls:

- read-only connection;
- allowlist statements;
- schema validation;
- query cost/limit;
- timeout;
- row limit;
- approval for writes.

---

## 6.3 Generated Shell

Highest risk.

Prefer domain tools rather than shell.

If unavoidable:

- sandbox;
- allowlist;
- no secrets;
- no privileged host access;
- resource limits.

---

## 6.4 Generated Infrastructure Changes

Use:

- diff;
- policy-as-code;
- plan/dry-run;
- review;
- staged rollout.

---

## 6.5 Tests Generated by AI

Generated tests themselves need evaluation.

They may:

- assert wrong behavior;
- mock implementation;
- skip edge cases.

---

## 6.6 Human Approval

Mandatory or strongly considered for:

- production deploy;
- destructive DB change;
- financial transaction;
- sensitive external communication.

Risk-based policy.

---

# 7. Engineering Depth

## 7.1 Dry Run

For safe preview:

```text
SQL EXPLAIN
IaC plan
deployment diff
email draft
refund simulation
```

Dry-run is powerful because it converts side effect into reviewable artifact.

---

## 7.2 Blast Radius

Before execution ask:

- which resources?
- how many records?
- reversible?
- backup/rollback?
- tenant scope?

# 10. Google Interview Drill

## Problem — Coding Agent Wants to Deploy Its Own Fix

### Clarify

- environment?
- test suite?
- change risk?
- canary?
- rollback?
- approval?

### First Approach

Allow agent to merge and deploy directly after tests.

Too broad for many enterprise contexts.

### Improve

```text
agent creates patch
→ static analysis
→ tests
→ security scan
→ human/code-owner review
→ staging/canary
→ monitor
→ rollout
```

For low-risk environments, automation can increase over time based on policy/evidence.

### Follow-Up

Define risk tiers for auto-merge/deploy.

# 11. Common Mistakes

1. Generated code runs because it compiles.
2. Generated SQL gets production credentials.
3. Generated shell has host access.
4. AI tests trusted blindly.
5. No dry-run.
6. No rollback.
7. Approval policy not risk-based.
8. No audit trail.

---

# 12. Best Practices

- treat generated output as untrusted;
- validate deterministic properties;
- sandbox execution;
- least-privilege credentials;
- dry-run before side effect;
- risk-based human approval;
- monitor and rollback.
